## 1. Stack
- Backend: Python 3.12 (`requires-python >=3.12,<3.13`), FastAPI, Pydantic v2, uvicorn, httpx, SQLAlchemy async + asyncpg (Postgres), Redis. Package manager: uv. File: `services/api/pyproject.toml`.
- iOS: SwiftUI, iOS 26 target, Swift 6 (`SWIFT_VERSION: "6.0"`), project generated by XcodeGen from `apps/ios/project.yml`.
- Client generation: Apple `swift-openapi-generator` (+ `swift-openapi-runtime`, `swift-openapi-urlsession`) builds the client from `apps/ios/Lifeline/Networking/openapi.yaml` at build time. That file is a copy of `contracts/openapi.yaml`. The app uses it only behind `protocol LifelineClient` (`LiveClient`, `MockClient`), ADR 0011.
- Contract source: Pydantic models in `services/api/lifeline_contracts/`. `contracts/build_openapi.py` (`make contract`) writes `contracts/openapi.yaml`. CI fails if the two differ.
- Server: Railway, project "lifeline". Two services from one Docker image (`services/api/Dockerfile`): `api` (uvicorn) and `worker` (`ROLE=worker`, `python -m lifeline_data.worker`, refreshes data sources). Public URL: `https://api-production-15615.up.railway.app`.

## 2. Contract
- `contracts/openapi.yaml` has 65 paths under `/v1`.

  - iOS Views never call the network. Only the server talks to outside sources ("the app talks only to our backend").

## 4. Adapters
- Fetch: `lifeline_data/base.py`. HTTP GET via httpx with a timeout (`http_timeout_seconds` = 8 s default), retries (`http_retries` = 3) with backoff and jitter on timeout, 429 and 5xx only, a circuit breaker (opens after 3 failures, half-open after 60 s), and payload validation.
- Cache order (`lifeline_data/hub.py` docstring):
  1. Fresh Redis entry inside the source TTL: returned as stored.
  2. Live fetch: status `live`.
  3. Stale Redis entry: status `cached`.
  4. Postgres last-good snapshot: status `cached`.
  5. Built-in sample: status `mock` (the app and trace show "sample").
- A source with no refresh for 2 x max(TTL, refresh interval) is reported as `cached`, not `live`.
- TTL examples (`lifeline_data/sources.py`): Bank of England 6 h, ONS 12 h, Nomis 1 day, postcodes 30 days. Other sources: see the same file (not checked).
- Missing API key (`key_env`): the source serves sample data with status `mock`.
- The macro table (all sources joined) is cached for 1 h (`macro_table_ttl_seconds`).

## 5. Engine (forecast)
- File: `lifeline_engine/forecast.py`. Functions: `compute`, `maths`, `income_plan`, `next_money`, `bills_between`, `usual_weeks`, `biggest_category`, `_run_out`, `_card_text`.
- Formula (`maths`):
  - left = money now + expected income - bills before the next money
  - buffer = buffer % (default 10) x left
  - per day = (left - buffer) / days, rounded DOWN to the penny (`ROUND_FLOOR`)
  - per week = per day x 7
  - The buffer takes the rounding remainder. When left <= 0, every amount is 0 (never a negative budget).
- Money now = current accounts only. Savings are not counted. An overdraft is negative.
- Days = tomorrow to the day before the next money. With no known next money: 28 days.
- Under 14 days (`SHORT_WINDOW_DAYS`): the card shows the total until the date (`to_spend` = per day x days), not a weekly figure.
- Next money (`income_plan`): the next payment of the main income source. Main = the recurring source with the largest amount per month. One-off money is never main. Other payments on the same day join it ("SAAS loan + bursary"). Other income before it counts as expected income.
- Bills (`lifeline_engine/money/recurring.py` `detect_recurring`):
  - Minimum charges per cadence: weekly 3, monthly 3, quarterly 2, yearly 2.
  - Subscriptions: each charge within 10% of the one before. One price rise up to 50% is allowed.
  - Bills: each charge within 50% of the median.
  - `bills_between` counts each due date from tomorrow to the day before the next money.
- Usual spending: the average of the last 4 weeks, without rent or bills. Raised by ONS CPI if the next money is over 6 weeks away.
- Run-out date (when running short) = today + whole days of left x 7 / usual weekly.

## 6. Penny
- Model: `CHAT_MODEL` = `claude-sonnet-5-5` (`lifeline_explain/config.py` `DEFAULT_CHAT_MODEL`). Engine text rewording uses `LLM_MODEL` (default `claude-opus-5-5`).
- System prompt: `lifeline_explain/prompts.py` `PENNY_SYSTEM`, version `penny-v9` (`PENNY_PROMPT_VERSION`).
- Tools: `ToolName` in `lifeline_explain/chat_tools.py`: `next_move`, `test_move`, `finance_summary`, `spend_prediction`, `cash_flow_projection`, `life_replay`, `forecast`, `forecast_what_if` and others (full list in that Literal). At most 5 tool calls per answer (`MAX_TOOL_CALLS`).
- Max tokens: 2048 in `lifeline_explain/llm.py`. Chat setting: not checked.
- Timeouts: one answer has a 12 s deadline by default (`chat_deadline` = min(`CHAT_TIMEOUT_SECONDS`, 2 x `LLM_TIMEOUT_SECONDS`)). Railway sets `CHAT_TIMEOUT_SECONDS=30`.
- Streaming: Anthropic SDK `messages.stream` (`lifeline_explain/chat_llm.py`). The server sends Server-Sent Events (`text/event-stream`) from `lifeline_api/routes/chat.py` `ask_penny_stream`. Event order: `verifying` comes before `bubble`.
- Scope (`lifeline_explain/scope.py`): a fixed rule runs before the model.
  - `off_topic_rule` catches homework, coding and celebrity questions. Those get one friendly line and 2 chips (`chips`), with no model call.
  - `topic_of` sorts the rest into money or student life. Money uses the strict number check. Student life uses the relaxed check and the "General knowledge" label.
  - `has_money_angle` adds a one-line money tip to a student-life answer.

## 7. Verifier
- File: `lifeline_explain/verifier.py`.
- Extraction: `extract_numbers` finds every number in the answer (£ amounts, percents, plain numbers, years) and records its kind and position.
- Match (`_close`, `number_matches`, `fact_matches`):
  - An exact value matches.
  - A value rounded to the decimals shown matches (£814 matches 813.96).
  - Otherwise the relative tolerance is 0.5% (`REL_TOLERANCE = 0.005`).
  - Percent facts match at 1 decimal place.
  - Dates match as day-of-month and year facts.
  - Each number must match a tool fact, the user's input, or an official fact.
- On fail: one rewrite request to the model with the failed numbers. If that also fails, `_template` builds a fixed answer from this turn's tool facts (`verified=false`). If no tool ran, the answer is "I could not confirm that number". If the model is down: "Penny is unavailable".
- Tests that prove it:
  - `tests/unit/explain/test_chat_speed_recheck.py::test_weekly_figure_never_denied_when_it_exists`
  - the VERIFY block in `make penny-trace`, which shows each number and its source with ✓ or ✗

## 8. Failure
- Source down: the hub falls back to Redis, then Postgres, then sample data. The status shows "saved copy" or "sample". The app keeps working.
- Claude down or over the deadline: Penny returns the template answer from the engine facts, or "Penny is unavailable" with an `error` event. Money screens do not use Claude.
- Server down: the app shows its saved copy (`DiskCache`), for example the sources hub. The exact offline text and the app request timeout were not checked.
- Timeouts: source HTTP 8 s x 3 tries; Redis socket 2 s; Penny 12 s default (30 s on Railway).

## 10. Security
- Secrets: only in environment variables (`.env` locally, Railway variables on the server). `.gitignore` excludes `.env`, `.env.*` (except `.env.example`), `*.p8`, `*.pem`, `*.key`, `*.mobileprovision`.
- Secret scan: gitleaks (`make secrets-scan` runs `gitleaks dir . --redact -c .gitleaks.toml`) before every commit. Last run: no leaks found.
- Auth: HS256 JWT (`lifeline_api/auth.py`) as a Bearer token, valid for 30 days. Sign-in with Apple, or a demo sign-in by device id.
- Rate limit: token bucket per user and per IP (`lifeline_api/ratelimit.py`). Redis-backed, with an in-memory fallback. Default 120 writes per minute per user (`rate_limit_per_minute`); reads have a larger limit.
- What leaves the device: the app talks only to our server, and it holds no keys.
  - Circles and rooms share only 0-100 ratios. No £ amount, balance, transaction or merchant goes to other users (ADR 0052).
- What goes to Claude: the question, and the tool facts for this turn (the user's own numbers from the engine). Keys, tokens and other users' data are never sent. penny-trace never prints prompts, keys or tokens (tested).

## 12. Weak points (honest)
1. Statements are sample or uploaded files, not live bank feeds. Open Banking was cut (ADR 0046). Next: one read-only Open Banking provider behind the same `FinanceSnapshot`.
2. Penny's free text depends on the model. The verifier checks numbers, not reasoning. A correct number in a weak argument still passes. Next: claim-level checks, and an eval set scored on every prompt change (`lifeline_eval/`).
3. Quick Life has known gaps: a fast finisher has to tap "Finish my run", INDEX still shows on the live screen, and Ask Penny is hidden in room games. Next: the ADR 0074 redesign (5 fixed questions, score out of 100, a waiting page).
