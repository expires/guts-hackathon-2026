### B2. Postgres stopped (12:40:34 to 12:40:35 UTC, restore ran in the same command)

| Call | Result |

- Recovery: 4 s after restart, the full probe passed (health ok, characters 200, create 201, age 200, get 200).
- The gate accepts this behaviour (error format, no crash, recovery after restart). See F1 for the improvement.

## Findings (non-blocking)

| ID | Owner | File:line | Finding | Suggested fix |
|---|---|---|---|---|
| F1 | W4 | `services/api/lifeline_api/routes/lives.py:53`, `services/api/lifeline_api/store.py:199` | With Postgres down, `GET /v1/characters` returns 500 `internal`. The endpoint only reads, but `_current_macro` writes the macro table to Postgres. `POST /v1/lives` also returns a generic 500. | In `/v1/characters`, skip `put_macro` or ignore its failure. For life writes, map store connection errors to 503 with code `store_unavailable`. |
| F2 | W1 | `services/api/lifeline_data/hub.py:210-214`, `hub.py:140-154` | With Redis down, `/v1/sources` reports every Tier 0 series source as `mock` ("not fetched yet"). The API still serves its in-process MacroTable, which was built from live data. A fresh-cache hit does not record local state, so the state is only in Redis. | Record local state on a fresh-cache hit (status from the stored rows), or keep the last shared state in memory. |
| F3 | W1 | `services/api/lifeline_data/cache.py:33`, `services/api/lifeline_data/sources.py:61` | postcodes TTL (30 days) is equal to `STALE_KEEP_SECONDS` (30 days). The stored entry expires when it becomes stale, so the `cached` fallback for postcodes cannot occur in production. The hub falls to `mock_postcode()` (area lookup, correct region). | Keep postcode entries longer than the TTL, for example 60 days. |
| F4 | W1 | `services/api/lifeline_data/adapters/postcodes.py:30`, `services/api/lifeline_data/hub.py:320` | HTTP 200 with no `result` field is treated as "postcode not found" and sets the state to `live`. | Treat 200 with no `result` as `PayloadError`. Return `None` only for HTTP 404. |
| F5 | W1 | `services/api/lifeline_data/hub.py:255-256` | `/v1/sources` reports postcodes as `cached` with no error before any lookup, including when the network is down (seen in A8 and B1). Nothing is cached at that time. | Report `mock` with "not fetched yet", the same as the other sources. |
| F6 | W1 | `services/api/lifeline_data/hub.py:116`, `hub.py:122` | The hub creates each `CircuitBreaker` without its injected clock. The breaker uses `time.monotonic`, so a test cannot control half-open timing through `DataHub(clock=...)`. Behaviour is correct. | Pass a monotonic clock argument from the hub to `CircuitBreaker`. |
